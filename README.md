# XYRO — локальный сканер веб-приложений

**Статус: исходная реализация 0.1.0. Готовность APK/EXE определяется результатами CI, а не наличием этого README.**

Одно Python-ядро, одинаковые адаптеры, коммиты инструментов, профили и интерфейс на Android и ПК. Моделей, LLM API и ИИ-планировщика в приложении нет. Проверки выполняются на устройстве. Для сканирования не нужен внешний исполнитель, root, Termux или платный API.

Android: 8.0+, ARM64 и x86_64. ПК: Windows x64 и Linux x64. Windows открывает интерфейс в локальном браузере; Android — во встроенном WebView. Телефон и ПК используют одинаковые настройки, но отличаются скоростью, памятью и возможностью долго работать в фоне.

## Что подключено

| Модуль | Использование |
|---|---|
| Собственное ядро | HTTP, cookie, защитные заголовки, проверяемые TLS-соединения, базовый обход ссылок |
| Katana | Обход сайта, JS и формы, без headless Chromium |
| gau | URL из публичных архивов; результаты фильтруются по заданному origin |
| Cariddi | Секреты, интересные endpoints, сообщения об ошибках |
| FinalRecon | Нативные Python-модули headers, DNS и TLS-сертификата |
| snallygaster | Открытые служебные и резервные файлы |
| Arjun | Поиск HTTP-параметров GET |
| Dalfox | XSS, штатный CLI без ИИ и MCP-сервера |
| Ghauri | Проверки SQLi BE, без дампа БД и SQL-shell |

AutoAR намеренно заменён собственным последовательным планировщиком: в исходном проекте есть ИИ-агент. Ни одна платформа не получает дополнительные модули, недоступные другой. Исходники Python-инструментов включены в vendor, точные коммиты всех инструментов записаны в tools.lock.json.

## Использование

1. Установите APK из успешного артефакта **XYRO-Android-APK** или распакуйте **XYRO-Windows-x64** и откройте XYRO.exe. Для Linux восстановите executable-бит: chmod +x XYRO _internal/bin/*.
2. Введите полный URL сайта, который вы вправе проверять.
3. Выберите «Разведка» или «Полный аудит», настройте глубину, скорость и бюджет этапа.
4. Смотрите статусы этапов, откройте журнал нажатием на статус. Отсутствующий модуль или таймаут означает неполное покрытие.
5. Сохраните ZIP: JSON-отчёт, HTML-отчёт и журналы инструментов.

Область — точный origin (схема + хост + порт). Для другого поддомена или порта создайте отдельную проверку. Архивные URL не являются подтверждёнными доступными страницами. «Полный аудит» — полный набор включённых адаптеров, а не обещание найти любую уязвимость.

## GitHub Actions

Workflow .github/workflows/build.yml запускается на push в main/master, pull request и вручную.

- Тесты ядра и проверка JavaScript.
- Сборка четырёх нативных инструментов из закреплённых исходников на Windows/Linux и для двух Android ABI.
- Упаковка EXE/Linux, затем запуск самопроверки уже упакованного приложения.
- Сборка APK с Python и нативными исполняемыми файлами внутри APK.
- Установка APK на эмулятор API 35 x86_64: запуск всех нативных CLI, Python-модулей и HTTP-проверки на локальном тестовом сервере.
- APK публикуется в артефакты только после успешной самопроверки; рядом — SHA256.

По умолчанию выпускается устанавливаемый **debug APK**, подписанный стандартным временным ключом CI. Между независимыми сборками ключ может отличаться: обновление поверх старой установки потребует удалить её, что удалит локальные отчёты. Для стабильного release-канала нужен постоянный приватный ключ; конфигурация release signing предусмотрена в android/app/build.gradle через XYRO_KEYSTORE, XYRO_STORE_PASSWORD, XYRO_KEY_ALIAS, XYRO_KEY_PASSWORD. Ключи не входят в исходники.

## Запуск из исходников

Нужны Python 3.11, Go 1.26+, Rust stable и Git:

    python -m venv .venv
    # Активируйте .venv в своей оболочке.
    python -m pip install -r requirements.txt
    python tools/build_native.py
    python desktop.py --selftest
    python desktop.py

Без bin/ работают Python-модули и базовое ядро; интерфейс покажет отсутствующие нативные модули. Такой запуск не является полной сборкой.

Сборка Android: Java 17, Gradle 8.11.1, SDK 35, NDK 28.2.13676358:

    python tools/build_native.py --android arm64-v8a --ndk /path/to/ndk
    python tools/build_native.py --android x86_64 --ndk /path/to/ndk
    python tools/prepare_android.py
    gradle -p android assembleDebug lintDebug

## Точные границы версии 0.1

- Нет headless-браузера: сложные SPA с маршрутизацией только в браузере покрываются не полностью на обеих платформах.
- Нет входа в аккаунты сайта, OAuth-автоматизации, проверки бизнес-логики, WebSocket fuzzing и автоматической эксплуатации.
- Внешние инструменты могут давать ложные срабатывания. Отчёт хранит их как кандидатов; отсутствующие заголовки — наблюдения, а не автоматически высокая критичность.
- Таймауты и отмена сохраняют журналы. При остановке нативного этапа его структурированный результат может ещё не быть готов; проверяйте сырой журнал.
- RPS — настройка отдельных инструментов, не точная глобальная квота: Cariddi запускается с одним worker и задержкой 1 сек.; TLS-туннели не расшифровываются локальным scope-proxy.
- Скрипты Python исполняются в отдельном процессе сканирования; запросы urllib3 ограничиваются origin. Нативным активным инструментам передаётся loopback scope-proxy. Это контроль направлений запросов, не ОС-песочница для недоверенного кода.
- DNS FinalRecon обращается к 1.1.1.1 / 8.8.8.8; gau — к сервисам архивов. Это сетевые источники данных, не ИИ.
- Android может остановить приложение из-за памяти, энергосбережения или ограничений производителя. Уведомление и wakelock уменьшают этот риск, но не устраняют его.
- lxml 5.3.0 и cryptography 42.0.8 закреплены из-за доступных Android wheels Chaquopy; это ограничение мобильной цепочки зависимостей. Нужен отдельный аудит/обновление нативных зависимостей перед production-релизом.
- Самопроверки запуска не заменяют полноценные регрессионные испытания XSS/SQLi и проверку на физическом ARM64-телефоне.

Отчёты сохраняются локально. Сырые журналы могут содержать найденные токены и ответные cookie; проверьте их перед передачей третьим лицам.

## Лицензии

Обвязка XYRO распространяется на условиях GPL-3.0-or-later. Исходные лицензии включены в licenses/ и vendor/. Исходники нативных инструментов доступны по repository/commit из tools.lock.json; скрипт сборки получает именно эти ревизии. Авторство исходных инструментов сохранено. Для распространения бинарных сборок предоставляйте также соответствующие исходники и этот проект.
